このブログは Next.js で自作していて、記事は MDX というファイルで管理しています。データベースや管理画面はなく、**記事のファイルを1つ追加するだけ**で新しい記事を公開できます。

この記事では、記事を書いてから公開するまでの流れを、自分用のメモも兼ねてまとめます。

## 記事ファイルを作る

記事は `content/posts` フォルダに置きます。新しい記事を書くときは、このフォルダに `.mdx` ファイルを1つ作ります。

```text title="フォルダの構成"
content/
└─ posts/
   ├─ hello-world.mdx
   ├─ nextjs-blog-setup.mdx
   └─ how-to-post.mdx   ← この記事
```

ファイル名は、そのまま記事のURLになります。たとえば `react-hooks.mdx` なら、URL は `/blog/react-hooks` です。ファイル名には英小文字、数字、ハイフンを使い、日本語や空白は避けるようにしています。

## 記事の情報を書く

ファイルの先頭には、`---` で囲んで記事の情報を書きます。この部分を「フロントマター」と呼びます。

```mdx title="content/posts/react-hooks.mdx"
---
title: "React の useState を理解する"
date: "2026-11-20"
description: "記事一覧に表示される短い説明文です。"
tags: ["React", "初心者向け"]
draft: true
---
```

それぞれの項目の役割は次のとおりです。

- `title`：記事のタイトル（必須）
- `date`：公開日。`"2026-11-20"` の形で書く（必須）
- `description`：記事一覧や、SNS でシェアされたときに表示される説明文
- `tags`：記事の分類。記事一覧の絞り込みボタンに自動で追加される
- `draft`：`true` の間は下書き。手元の開発サーバーでだけ表示され、公開サイトには出ない

日付を違う形で書くと、ビルドのときにエラーで教えてくれるようにしてあります。書き間違えたまま公開してしまう心配がありません。

## 本文を書く

本文は Markdown という書き方で書きます。記号を付けるだけで、見出しや箇条書きになります。

````mdx title="本文の書き方の例"
普通の文章は、そのまま書きます。

## 大見出し

### 小見出し

- 箇条書き
- **太字** や `コード` も使える

```tsx title="Counter.tsx"
const [count, setCount] = useState(0);
```

[リンクの文字](https://example.com)
````

このブログでは、`##` の大見出しに「01」「02」のような番号が自動で付き、記事の左側の目次にも並びます。

コードは ` ```tsx title="Counter.tsx" ` のように書くと、色が付き、上にファイル名、右上にコピーボタンが表示されます。画像を載せたいときは、`public/images` フォルダに画像を置いて、`![画像の説明](/images/画像の名前.png)` と書きます。

## 手元で表示を確かめる

書いている途中の記事は、開発サーバーで確認します。

```bash title="ターミナル"
npm run dev
```

ブラウザで `http://localhost:3000/blog` を開くと、記事一覧に下書きの記事も表示されます。ファイルを保存するたびに表示が更新されるので、見た目を確かめながら書けます。

## 公開する

書き終わったら、フロントマターの `draft: true` を `false` に変えて、GitHub にプッシュします。

```bash title="ターミナル"
git add content/posts/react-hooks.mdx
git commit -m "Add post about useState"
git push
```

このブログは Vercel で公開していて、GitHub の `main` にプッシュすると、自動でサイトが作り直されます。1分ほどで公開サイトに反映され、トップページ、記事一覧、サイトマップにも自動で追加されます。

パソコンに開発環境がないときは、GitHub の画面から直接ファイルを作ることもできます。リポジトリの `content/posts` を開いて「Add file」から「Create new file」を選び、保存（Commit）すれば、同じように公開されます。

## まとめ

記事を投稿する流れは、次の4ステップです。

1. `content/posts` に `.mdx` ファイルを作る
2. 先頭に記事の情報を書き、本文を Markdown で書く
3. `npm run dev` で表示を確かめる
4. `draft` を `false` にして GitHub にプッシュする

ファイルを1つ追加するだけで記事が増えていくので、思い立ったときにすぐ書けるのが、自作ブログのいいところだと感じています。
