ブログを始めるとき、多くの人が使うのが WordPress（ワードプレス）です。管理画面にログインして、文章を書いて、「公開」ボタンを押す。それだけで記事が世界中に公開されます。

このブログは WordPress を使わず、自分でプログラムを書いて作りました。そのため、記事の投稿のしかたも WordPress とは少し違います。この記事では、WordPress と比べながら、このブログで記事を投稿する流れを紹介します。

## WordPress との違い

いちばん大きな違いは、**記事が「ファイル」として保存される**ことです。WordPress では、書いた記事はサーバーの中のデータベース（情報をしまっておく大きな棚のようなもの）に保存されます。このブログでは、記事1本がパソコンの中のファイル1つになります。Word で書いた文書が1つのファイルになるのと同じ感覚です。

どちらが優れているというより、向いている人が違います。

- **WordPress が向いている人**：パソコンに詳しくなくてもすぐに始めたい人、スマートフォンからも気軽に書きたい人
- **自作ブログが向いている人**：デザインや機能を自由に作り込みたい人、作る過程そのものを楽しみたい人

自作ブログには、表示が速い、ログインする管理画面がないので乗っ取られる心配が少ない、サーバー代がかからない、といった良さもあります。一方で、最初の仕組みづくりには、プログラムの知識が必要です。

## 投稿の流れ（全体像）

このブログで記事を公開するまでの流れは、次の4ステップです。

1. 記事のファイルを作る
2. タイトルや日付と、本文を書く
3. 自分のパソコンで見た目を確かめる
4. GitHub に送って公開する

ここで出てくる2つのサービスを、本づくりにたとえて紹介します。

- **GitHub（ギットハブ）**：原稿の保管庫。書いた記事のファイルを預けておく場所です。いつ、どこを書き直したかの記録も残ります。
- **Vercel（バーセル）**：自動で本を作って本屋に並べてくれる係。GitHub に新しい原稿が届くと、それを読み取ってサイトを作り直し、インターネットに公開してくれます。

つまり、**原稿（記事）を保管庫（GitHub）に入れると、あとは係（Vercel）が自動で公開してくれる**、という仕組みです。WordPress の「公開」ボタンの役割を、この2つのサービスが分担しています。

## 記事のファイルを作る

WordPress でいう「新規投稿」にあたる作業です。

記事は `content/posts` というフォルダに置きます。新しい記事を書くときは、このフォルダにファイルを1つ作ります。

```text title="フォルダの中身"
content/
└─ posts/
   ├─ hello-world.mdx
   └─ how-to-post.mdx   ← この記事
```

ファイル名の最後は `.mdx` にします。ファイル名は、そのまま記事のアドレス（URL）になります。たとえば `react-hooks.mdx` という名前なら、記事のアドレスは `/blog/react-hooks` です。ファイル名には、英語の小文字、数字、ハイフン（-）を使います。

## タイトルや日付を書く

WordPress でいう、編集画面の右側にある「カテゴリー」や「公開日」などの設定欄にあたる部分です。

このブログでは、ファイルのいちばん上に、`---` で挟んで書きます。

```mdx title="react-hooks.mdx の先頭"
---
title: "React の useState を理解する"
date: "2026-11-20"
description: "記事一覧に表示される短い説明文です。"
tags: ["React", "初心者向け"]
draft: true
---
```

それぞれの意味は次のとおりです。

- `title`：記事のタイトル
- `date`：公開日
- `description`：記事一覧や、SNS でシェアされたときに表示される紹介文
- `tags`：記事の分類（WordPress のカテゴリーやタグにあたる）
- `draft`：`true` にしておくと「下書き」になり、公開サイトには表示されない

WordPress の「下書き保存」と同じように、`draft: true` のままにしておけば、書きかけの記事が誤って公開されることはありません。

## 見た目を確かめる

WordPress の「プレビュー」ボタンにあたる作業です。

自分のパソコンで、ブログを一時的に表示させる命令を実行します。

```bash title="ターミナル（命令を入力する画面）"
npm run dev
```

ブラウザで `http://localhost:3000/blog` を開くと、書いている記事が表示されます。`localhost` は「自分のパソコン」という意味で、ここに表示されたものは自分にしか見えません。ファイルを保存するたびに表示が自動で更新されるので、見た目を確かめながら書き進められます。

## 公開する

WordPress の「公開」ボタンにあたる作業です。

まず、ファイルの先頭の `draft: true` を `draft: false` に変えて、下書きを解除します。そのあと、ファイルを GitHub に送ります。

```bash title="ターミナル"
git add content/posts/react-hooks.mdx
git commit -m "useState の記事を追加"
git push
```

3行の命令は、それぞれ「このファイルを送る準備をする」「変更の内容にメモを付けて記録する」「GitHub に送る」という意味です。

GitHub に記事が届くと、Vercel が自動でサイトを作り直します。1分ほどで公開サイトに記事が表示され、トップページや記事一覧にも自動で並びます。

ちなみに、命令を打つのが難しいときは、GitHub のホームページから直接ファイルを作ることもできます。ブラウザでファイルを作って保存するだけなので、WordPress の管理画面に近い感覚で投稿できます。

## まとめ

WordPress と比べると、このブログの投稿のしかたは次のように対応しています。

- 新規投稿 → `content/posts` にファイルを作る
- 設定欄 → ファイルの先頭にタイトルや日付を書く
- エディタ → Markdown の記号を使って本文を書く
- プレビュー → `npm run dev` で自分のパソコンに表示する
- 公開ボタン → GitHub に送ると、Vercel が自動で公開する

ボタン1つで公開できる WordPress に比べると、手順は少し多く見えます。それでも、記事が自分の手元にファイルとして残り、デザインも機能も自由に作れるのは、自作ブログならではの良さです。ブログを作ること自体も、Web開発のよい勉強になっています。
